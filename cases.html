Backend / Architecture

Case Jungle

Case técnico

Um comando. Um efeito financeiro. Locks e idempotência persistente para coordenar saldo, ledger e mensagens.

FOCO

Modelagem de domínio, concorrência, transações SQL, integração assíncrona, observabilidade e desenho de testes de consistência.

TECNOLOGIAS

TypeScript · NestJS · Bun · PostgreSQL · TypeORM · SQS · Docker

O problema
Processar operações de apostas sem duplicar efeitos financeiros e manter consistência entre saldo, transações e ledger.
A implementação
WagerService usa advisory lock e SELECT FOR UPDATE. O schema contém constraints, ledger imutável por trigger e reconciliação diferida. Workers implementam publicação da outbox e consumo de SQS. Testes incluem 50 entregas repetidas e duas apostas concorrentes. Money encapsula decimal.js.
Como as partes se conectam
HTTP / SQS → serviço de aplicação → domínio Money / Wallet / WagerTransaction → transação PostgreSQL (saldo + ledger + inbox + outbox) → worker SQS. Docker Compose inclui LocalStack e Nginx.
Escopo atual

Case técnico executado em Bun, com infraestrutura local descrita no repositório. Autenticação ainda não implementada; testes não executados nesta revisão.

Data / Business Intelligence

Retail Fraud Detection

Análise exploratória

Dados antes de conclusões. 100.000 transações para investigar padrões e formular hipóteses de negócio.

FOCO

Qualidade de dados, estatística descritiva, visualização, formulação de hipóteses e comunicação de implicações para o negócio.

TECNOLOGIAS

Python · pandas · NumPy · matplotlib · seaborn

O problema
Investigar padrões associados a fraude em transações de varejo e apoiar hipóteses de triagem operacional.
A implementação
Recontagem independente do CSV: 100.000 registros, 21 colunas e nenhuma célula vazia. Internacionais: 34.219 fraudes em 49.801 operações (68,71%); domésticas: 13.289 em 50.199 (26,47%). Mobile: 51,93%; Tablet: 45,65%; Desktop: 44,92%. O script verifica nulos, descreve distribuições e produz boxplots, contagens e correlações.
Como as partes se conectam
CSV → pandas / NumPy → estatísticas e agrupamentos → matplotlib / seaborn → interpretação no README.
Escopo atual

Análise exploratória da base estudada. Não é um modelo preditivo nem comprovação de redução de fraude.

Chat Furioso

Protótipo integrado

Uma conversa conectada a serviços. Estado de interface, mensagens assíncronas e feedback durante a resposta do webhook.

FOCO

TECNOLOGIAS

React · JavaScript · Vite · CSS · Webhook n8n

O problema

Know Your Fan

Protótipo com pendências

Cadastro com etapas conectadas. Formulário, upload documental e webhook organizados em uma jornada de identificação.

FOCO

Formulários, estado, upload em base64, consumo de serviços externos e encadeamento de etapas assíncronas.

TECNOLOGIAS

React · JavaScript · Vite · Express · IdAnalyzer · Webhook n8n

O problema
Estruturar o cadastro de fãs e condicionar o envio dos dados a uma etapa de verificação documental.
A implementação
FanForm.js implementa upload, chamada da API, comparação do primeiro nome e envio posterior ao webhook. server.js define a rota Express. api/idanalyzer.js exporta verifyDocument(imageBase64), não um handler HTTP de Vercel.
Como as partes se conectam
Fluxo no cliente: React → POST /api/idanalyzer → retorno ao React → checagem de success e nome → POST do React ao n8n. Existe um servidor Express separado que chama o módulo IdAnalyzer. Não é uma cadeia serverless funcional comprovada.
Escopo atual

Protótipo com backend pendente de correções. A função Vercel e o fluxo completo não foram validados; não disponível como demo pública.

MMORPG em Python

Projeto autoral

Engenharia por trás do jogo. Desenvolvimento de um MMORPG com toda a implementação de backend em Python.

CONTRIBUIÇÃO INFORMADA

Desenvolvimento integral do backend do jogo em Python.

TECNOLOGIA CONFIRMADA PELO AUTOR

Python. Frameworks, banco de dados e infraestrutura ainda não documentados neste case.

O projeto
Um MMORPG autoral apresentado como trabalho de backend. O foco deste case é a implementação do software que sustenta o jogo, além da sua apresentação visual.
O papel no portfólio
Mostrar o uso de Python em desenvolvimento de jogos, complementando sua aplicação em automação operacional e análise de dados. O projeto amplia a narrativa de engenharia para um domínio diferente dos dashboards e aplicações web.
Escopo de autoria
O autor informa ter desenvolvido todo o backend em Python. Essa afirmação se refere ao backend; não implica que o cliente gráfico, a arte ou todas as demais partes do jogo tenham sido feitos na mesma linguagem.
Detalhamento técnico
O código e a documentação ainda não foram disponibilizados nesta revisão. A divisão de módulos, as regras do jogo, a persistência e a comunicação entre jogadores serão descritas a partir da implementação, sem presumir componentes pelo nome MMORPG.
Sobre as informações deste case

Descrição baseada nas informações fornecidas pelo autor. Repositório, demonstração e estágio de desenvolvimento ainda não informados. Multiplayer, quantidade de jogadores simultâneos e infraestrutura não foram verificados.
